# HMIS — Project CLAUDE.md

Complete reference for the entire project. Every new feature and every code change must follow these rules exactly.

---

## Project Overview

**HMIS** (Hospital Management Information System) is a Flutter mobile app supporting three roles:
- **Patient** — books appointments, views doctors
- **Doctor** — manages appointments and patient records
- **Admin** — manages doctors, patients, and all appointments (no UI login — Firestore only)

**Tech Stack:** Flutter · Firebase (Auth + Firestore + FCM) · Riverpod (codegen) · GoRouter · EasyLocalization · Hive

## Feature Architecture — The Pattern Every Feature Follows

Every feature has four layers. Never skip a layer, never merge two layers into one file.

```
lib/features/<feature_name>/
├── models/
│   ├── <feature>_states.dart         # Immutable state class
│   └── [other models]                # Data models for this feature
├── providers/
│   ├── <feature>_provider.dart       # Riverpod notifier (business logic)
│   └── generated/
│       └── <feature>_provider.g.dart # DO NOT EDIT — generated by build_runner
├── services/
│   ├── remote/
│   │   └── <feature>_remote_service.dart  # Firebase/Firestore only
│   └── local/                             # Only if this feature needs caching
│       └── <feature>_local_service.dart   # Hive cache only
└── views/
    ├── <feature>_page.dart
    └── widgets/                      # Feature-specific widgets (not shared)
```

## State Model Pattern

Every feature has a `<Feature>States` class:

```dart
class SomeStates {
  final List<SomeModel> items;
  final bool isLoading;
  final String? errorMessage;   // null = no error

  const SomeStates({
    this.items = const [],
    this.isLoading = false,
    this.errorMessage,
  });

  factory SomeStates.initial() => const SomeStates();

  SomeStates copyWith({
    List<SomeModel>? items,
    bool? isLoading,
    String? errorMessage,
    bool clearError = false,     // ← always include this flag
  }) {
    return SomeStates(
      items: items ?? this.items,
      isLoading: isLoading ?? this.isLoading,
      errorMessage: clearError ? null : (errorMessage ?? this.errorMessage),
    );
  }
}
```

**Rules:**
- `copyWith(clearError: true)` — call at the start of every async action
- `copyWith(isLoading: false, errorMessage: '...')` — call on catch
- Never mutate a list — always produce a new list (`.where().toList()`, `.map().toList()`)
- Never store passwords, tokens, or secrets in any state class

## Provider Pattern

```dart
import 'package:riverpod_annotation/riverpod_annotation.dart';
part 'some_feature.g.dart';

@Riverpod(keepAlive: true)
class SomeFeature extends _$SomeFeature {
  late final SomeRemoteService _remoteService;
  late final SomeLocalService _localService;

  @override
  Future<SomeStates> build() async {
    _remoteService = SomeRemoteService();
    _localService = SomeLocalService();

    // 1. Try to get cached data first
    final cached = await _localService.getCachedData();
    
    if (cached != null) {
      // Trigger background refresh without blocking the UI
      _refreshBackground();
      return cached;
    }

    // 2. If local is empty, wait for remote
    return _fetchAndSave();
  }

  Future<SomeStates> _fetchAndSave() async {
    final remoteData = await _remoteService.fetchAll();
    await _localService.saveData(remoteData);
    return remoteData;
  }

  Future<void> _refreshBackground() async {
    try {
      final newData = await _fetchAndSave();
      state = AsyncValue.data(newData);
    } catch (e, st) {
      // In background refresh, we usually don't override 
      // the existing data with an error state
      log('Background refresh failed: $e');
    }
  }

  Future<void> doSomething(String id) async {
    // 1. Loading state
    state = const AsyncValue.loading();

    // 2. Execute with Guard
    state = await AsyncValue.guard(() async {
      // Remote call
      await _remoteService.doSomething(id);
      
      // Update local storage
      await _localService.updateItemLocally(id);
      
      // Return updated local data
      return await _localService.getCachedData() ?? SomeStates();
    });
  }

  // Example of manual error setting if needed
  void setManualError(Object error, StackTrace st) {
    state = AsyncValue.error(error, st);
  }

  // Example of manual data setting
  void setManualData(SomeStates data) {
    state = AsyncValue.data(data);
  }
}
```

**After any change to a provider file, regenerate:**
```bash
dart run build_runner build --delete-conflicting-outputs
```

## Remote Service Pattern

```dart
class SomeRemoteService {
  final _db = FirebaseFirestore.instance;

  Future<List<SomeModel>> getAll() async {
    final snap = await _db.collection(Constants.someKey.name).get();
    return snap.docs.map((d) => SomeModel.fromJson(d.data())).toList();
  }

  Future<void> delete(String id) async {
    await _db.collection(Constants.someKey.name).doc(id).delete();
  }
}
```

**Rules:**
- No Riverpod, no UI, no BuildContext — pure data layer
- Instantiated with `SomeRemoteService()` inside the provider's `build()`
- Throws on error — the provider's `catch` handles it
- All Firestore collection names come from `Constants.*` enum

## Local Service Pattern (cache-first features)

```dart
class SomeLocalService {
  final _storage = LocalStorage.instance;

  Future<void> saveItems(List<SomeModel> items) async {
    final json = items.map((i) => jsonEncode(i.toJson())).toList();
    await _storage.save(key: Constants.someKey.name, value: json);
  }

  List<SomeModel>? getItems() {
    final raw = _storage.get<List>(Constants.someKey.name);
    if (raw == null) return null;
    return raw.map((e) => SomeModel.fromJson(jsonDecode(e))).toList();
  }
}
```

**Rules:**
- Never `await` a local save inside a provider action — use `unawaited()`
- Only features that need offline/cache support have a local service

## View Pattern

```dart
class SomePage extends ConsumerWidget {           // or ConsumerStatefulWidget
  static const routeName = '/some-page';

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final asyncState = ref.watch(someProvider);

    // Side-effects: errors, navigation — NEVER inside build() body
    ref.listen(someProvider, (_, next) {
      final msg = next.value?.errorMessage;
      if (msg != null) GlassySnackbar.showError(context, msg);
    });

    return asyncState.when(
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (e, _) => Center(child: Text('${LocaleKeys.new_key.tr()} $e')),
      data: (state) {
        // Build UI from state
        return Scaffold(...);
      },
    );
  }
}
```

**Rules:**
- `ref.watch(provider)` — reactive data, always in build
- `ref.listen(provider, ...)` — side-effects (errors, navigation), never navigate inside build
- `ref.read(provider.notifier).action()` — trigger actions (button press, etc.)
- Pull-to-refresh: `onRefresh: () => ref.read(someProvider.notifier).refresh()`
- Use `ConsumerStatefulWidget` only when local UI state is needed (e.g., search query, text controllers)
- All controllers disposed in `dispose()`
- Error display: always `GlassySnackbar.showError(context, message)`
- `state.isLoading` disables action buttons — pass `null` to `onPressed`/`onTap`

## Navigation — GoRouter Rules

**Always use go_router. Never use `Navigator.push(MaterialPageRoute(...))`.**

```dart
// Navigate forward
context.pushNamed(SomePaage.routeName);

// Navigate forward with data
context.pushNamed(SomePaage.routeName, extra: someModel);

// Replace (no back button)
context.go(SomePaage.routeName);

// Pop
context.pop();
```

**Registering a new route** in `lib/core/router/mobile/router.dart`:
```dart
GoRoute(
  path: SomePage.routeName,
  name: SomePage.routeName,
  builder: (context, state) {
    final extra = state.extra as SomeModel?;  // typed, nullable
    return SomePage(data: extra!);
  },
),
```

**Rules:**
- Every page class has `static const routeName = '/route-name'`
- Pass model objects via `extra` — never via query params
- Dialogs and bottom sheets use `Navigator.pop(context)` — this is allowed
- Never navigate inside `build()` — always inside `ref.listen(...)`

## Localization — Translation System

**Package:** `easy_localization`  
**Translation files:** `assets/translations/en.json` and `assets/translations/ar.json`  
**Generated files (DO NOT EDIT):**
- `lib/generated/locale_keys.g.dart` — type-safe key constants
- `lib/generated/codegen_loader.g.dart` — JSON-to-Dart loader

### How to Add a New Translation Key

**Step 1** — Add the key to both JSON files:

`assets/translations/ar.json`:
```json
{
  "existing_key": "قيمة موجودة",
  "new_key": "القيمة الجديدة"
}
```

`assets/translations/en.json`:
```json
{
  "existing_key": "Existing value",
  "new_key": "New value"
}
```

**Step 2** — Regenerate the locale keys file:
```bash
dart run easy_localization:generate -S assets/translations -s en.json
```

**Step 3** — Use in code:
```dart
import 'package:easy_localization/easy_localization.dart';
import 'package:hmis/generated/locale_keys.g.dart';

// Preferred — type-safe (IDE autocomplete)
Text(LocaleKeys.new_key.tr())

### Nested Keys

```json
{
  "auth": {
    "login": "تسجيل الدخول",
    "register": "إنشاء حساب"
  }
}
```

```dart
Text(LocaleKeys.auth_login.tr())   // nested separator is underscore
```

### Keys with Parameters

```json
{ "welcome": "مرحباً {name}" }
```

```dart
Text(LocaleKeys.welcome.tr(namedArgs: {'name': user.name}))
```

### Language Switching

Language is changed through `settingsProvider`:
```dart
ref.read(settingsProvider.notifier).changeLanguage(Language.arabic);
```

Language is persisted in Hive and restored on app start. The app rebuilds automatically via EasyLocalization context.

### Language Detection Helper

`getLanguageCodeHelper()` in `lib/core/helper/help_functions.dart` detects device locale and falls back to Arabic if unsupported.

## Adding a New Feature — Checklist

1. Create the folder: `lib/features/<feature_name>/`
2. Create `models/<feature>_states.dart` — immutable state with `copyWith(clearError:)`
3. Create `models/<feature>_model.dart` — data model with `fromJson`/`toJson`/`copyWith`
4. Create `services/remote/<feature>_remote_service.dart` — pure Firestore, no Riverpod
5. (If caching needed) Create `services/local/<feature>_local_service.dart`
6. Create `providers/<feature>_provider.dart` with `@Riverpod(keepAlive: true)`
7. Create `providers/generated/` folder (empty — build_runner will populate it)
8. Run `dart run build_runner build --delete-conflicting-outputs`
9. Create `views/<feature>_page.dart` — use `ref.watch`, `ref.listen`, `ref.read.notifier`
10. Add route to `lib/core/router/mobile/router.dart` with `static const routeName`
11. Add translation keys to both JSON files and run codegen

## Patterns to Never Break

- `@Riverpod(keepAlive: true)` — all feature providers must stay alive (global singletons)
- Never `ref.read(provider)` in `build()` — use `ref.watch()`
- Never navigate inside `build()` — always `ref.listen()`
- Never show snackbars inside `build()` — always `ref.listen()`
- Never use `Navigator.push(MaterialPageRoute(...))` — always `context.push()` or `context.go()`
- Never mutate state directly — always use `copyWith()`
- Always `clearError: true` at the start of async actions
- Never await `localService.save*()` calls — use `unawaited()`
- Admin accounts created manually in Firestore only — no registration page
